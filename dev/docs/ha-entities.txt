# liste que la carte déclare elle-même (API native ESPHome sur 172.16.0.205) — 24 entités
# déclarées par le firmware, 24 retrouvées dans HA sous ce préfixe. Relevés précédents :
# l'appareil s'est d'abord appelé « Jardin Station Vevor 7-en-1 » (préfixe

# renommage d'appareil renomme les 24 entity_id d'un coup. check_ha_card.py vérifie la carte
# contre CETTE liste, jamais contre une reconstruction.
#
# PLUS AUCUNE EXCEPTION depuis le 05/10/2026 : l'ancienne entrée de nœud ESPHome a été
# nettoyée dans HA, et Illuminance est revenue sous le préfixe d'appareil
# (sensor.jardin_vevor_7_in_1_weather_station_illuminance, plateforme « esphome »).
# L'ancien sensor.esp32_weather_illuminance n'existe plus — absent de /api/states — alors que
# la carte s'y référait encore : l'encart de luminosité et le bandeau lisaient 0 lx.
#
# Ne sont PAS listés ici, bien qu'attachés au même appareil : cinq compteurs d'utilité créés
# par le propriétaire, les entités « Rain Hour / Day / Week / Month / Year » de la carte
# (rain_hour, rain_day, rain_week, rain_month, rain_year). Plateforme mesurée : utility_meter
# (registre des entités de HA), source sensor.jardin_vevor_7_in_1_weather_station_rain_total.
# Ce sont des helpers HA, pas des entités du firmware : les ajouter ferait échouer la
# comparaison firmware ↔ HA du contrôle, qui doit rester une égalité.
#
# Rafraîchir après tout renommage, changement de nom d'appareil ou nouvelle entité :
#   1. Home Assistant → Outils de développement → États, filtrer « vevor », coller les
#      couples nom / entity_id ci-dessous (un par domaine : binary_sensor, sensor, …) ;
#   2. .venv/bin/python dev/tools/check_ha_card.py   → doit rendre 0 échec.
